# ארכיטקטורה ומבנה הקבצים

## החלטת טכנולוגיה
**HTML + CSS + JavaScript טהור, ללא שלב build ובלי תלויות חיצוניות.**

נימוק: בסביבת הפיתוח לא היה Node.js מותקן, ובנוסף אתר סטטי מאפשר פריסה מיידית על כל שרת/אחסון (Netlify, IIS, Apache) ללא תחזוקה. אין CDN חיצוני — כל הקוד מקומי, מה שמפחית חשיפה בהקשר של מידע רפואי רגיש.

## עץ הקבצים

```
אתר ללקוחות/
├── index.html              מסך כניסה (הזדהות בת״ז + קוד אישי)
├── dashboard.html          האזור האישי — כל התצוגות
├── README.md               הוראות הפעלה
└── assets/
    ├── css/style.css       גיליון עיצוב יחיד, RTL מלא, משתני CSS
    └── js/
        ├── data.js         נתונים + CaseStore + Auth
        └── dashboard.js    רינדור כל הרכיבים + לוגיקת העלאה
```

## שכבות

| שכבה | קובץ | אחריות |
|---|---|---|
| נתונים | `data.js` → `CLAIM_STAGES`, `DEMO_CLIENTS` | קטלוג שלבי התביעה + תיקי הדגמה |
| אחסון | `data.js` → `CaseStore` | טעינת תיק, שמירת שינויים ב-`localStorage` |
| אימות | `data.js` → `Auth` | login / logout / `requireLogin()` להגנה על עמוד |
| תצוגה | `dashboard.js` | רינדור ציר שלבים, מסמכים, סטטיסטיקות, הודעות |
| עיצוב | `style.css` | טוקנים (`--navy`, `--gold`), רספונסיביות, RTL |

## שפת עיצוב
- **כחול־נייבי כהה** (`#0f2540`) — סמכותיות משפטית.
- **זהב** (`#b8935a`) — הדגשות ופעולות ראשיות.
- קוד צבע לסטטוס: אדום = חסר, כתום = בבדיקה, ירוק = אושר.
- כל הפריסה `dir="rtl"` עם `inset-inline-start` במקום `left/right`, כדי שהעיצוב יישאר תקין גם בשפה נוספת.

## נקודות החלפה לשרת אמיתי
שתי נקודות בלבד צריכות שינוי:
1. `Auth.login()` — להחליף בקריאת POST לשרת שמחזירה session cookie.
2. `CaseStore.load()` / `saveDocument()` — להחליף ב-`fetch` ל-API.
