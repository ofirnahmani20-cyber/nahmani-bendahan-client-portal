# מסמך הגדרות מאגר - טיוטה

> ⚠️ **טיוטה שנכתבה מתוך הקוד, לא חוות דעת משפטית.** היא מתארת מה המערכת עושה בפועל נכון ל-25.11.2026. היא נועדה לחסוך לאיש המקצוע (ממונה אבטחה / יועץ פרטיות) את שלב איסוף העובדות, לא להחליף אותו. כל מקום שמסומן **[לאישור]** הוא החלטה או פרשנות משפטית שאינה שלי.
>
> הבסיס: חוק הגנת הפרטיות התשמ"א-1981 (כולל תיקון 13) ותקנות הגנת הפרטיות (אבטחת מידע) התשע"ז-2017, תקנה 2 - מסמך הגדרות מאגר.

## 1. פרטי המאגר

| | |

| שם המאגר | תיקי לקוחות - משרד נחמני-בן דהן |
| בעל המאגר | המשרד **[לאישור: הישות המשפטית - שותפות / חברה / עוסק, טרם נוסדה]** |
| מנהל המאגר | **[לאישור: עו"ד שותף]** |

| מיקום | **מתוכנן:** שרת יחיד בענן עם אזור בישראל. כרגע פיתוח מקומי בלבד, בלי נתונים אמיתיים |
| רמת אבטחה | **[לאישור]** - ראו §8 |

## 2. מטרות המאגר

1. ניהול תביעות של לקוחות מול המוסד לביטוח לאומי ומשרד הביטחון (נכות כללית, נכות מעבודה, נכי צה"ל וכו').
2. איסוף המסמכים הרפואיים והאחרים הדרושים לתביעה, בדיקתם והגשתם.
3. עדכון הלקוח על מצב התיק, תזכורות ועדות ומסמכים חסרים.
4. מעקב אחר תשלומי הגוף ושכר הטרחה לפי הסכם.

**מה המאגר אינו משמש לו:** שיווק, דיוור, העברה לצד שלישי לתמורה, או פרופיילינג. "לימוד מתיקים קודמים" (docs/10) **אינו ממומש**, ויופעל רק עם הסכמה מפורשת (ראו docs/14).

## 3. סוגי המידע

| קטגוריה | דוגמה | איפה | הגנה |
|---|---|---|---|
| מזהים | שם, טלפון, אימייל | `clients` | גישה לפי הרשאה |
| ת"ז | | `clients.national_id_enc` / `_lookup` | **מוצפנת** (Fernet); לחיפוש - HMAC בלבד |
| מידע רפואי | מסמכים, סיכומי אשפוז, חוות דעת | `document_files` + דיסק | **AES-256-GCM** לכל קובץ, מפתח נגזר לקובץ |
| טקסט שחולץ ממסמכים | OCR, סיווג, עובדות | `document_pages`, `document_facts` | מוצפן, מקושר לעמוד |
| מידע משפטי | שלבי תיק, החלטות ועדה, משימות | `cases`, `case_*` | גישה לפי אחראי התיק |
| מידע כספי | קצבאות שהתקבלו, שכר טרחה | `benefit_payments`, `fee_*` | גישה לפי הרשאה; רישום מבוטל ולא נמחק |
| התכתבות | הודעות, תגובות לקוח, היסטוריית משלוח | `messages`, `case_conversation`, `message_deliveries` | |
| נתוני גישה | sessions, יומן ביקורת | `sessions`, `audit_log` | hash של הטוקן בלבד; היומן לכתיבה בלבד בקוד |
| הגבלת קצב | | `rate_limit_hits` | HMAC בלבד, נמחק תוך יממה |

**מידע רגיש** במובן החוק: מידע רפואי, ומידע על מצבו הכלכלי של אדם. **[לאישור]** אם מידע על הליך משפטי נחשב כאן מידע רגיש נוסף.

## 4. מקורות המידע

- **הלקוח עצמו:** העלאה בפורטל, תגובות, פרטים שמסר בפתיחת התיק.
- **תיבת המייל של המשרד** (`mail_intake.py`): קבצים מצורפים בלבד. נושא וגוף ההודעה **אינם נשמרים**; כל קובץ משויך לתיק בידי אדם.
- **הצוות:** הזנה ידנית.
- **גופים ציבוריים** (ב"ל, משרד הביטחון): מכתבים שהלקוח או המשרד מקבלים ומעלים. **אין** גישה אוטומטית לאתרים שלהם.

## 5. מי ניגש למידע

| תפקיד | גישה | אימות |
|---|---|---|
| לקוח | התיק שלו בלבד | קוד SMS חד-פעמי |
| איש צוות | התיקים שהוא אחראי עליהם בלבד (`auth.case_scope`) | סיסמה (bcrypt) + TOTP, חובה ב-production |
| מנהל (שותף) | כל תיקי המשרד, איפוס TOTP לצוות | כנ"ל |
| מערכת (worker, notifier) | לפי שירות, בלי ממשק משתמש | אין גישה לרשת מבחוץ, למעט notifier |

**רשימת בעלי ההרשאה** בפועל נשמרת בטבלת `users` ומתעדכנת שם. **[לאישור]** - תקנה 8 מחייבת רשימה מעודכנת; מוצע לייצא אותה רבעונית ולשמור עם הנוהל.

## 6. העברת מידע לגורמים חיצוניים

| גורם | מה מקבל | איפה | מצב |
|---|---|---|---|
| ספק ענן (אחסון ושרת) | הכול, **מוצפן במנוחה** (קבצים; ת"ז) - מפתחות הקבצים אינם אצלו | ישראל **[לאישור: ספק]** | טרם נבחר |
| ספק SMS | מספר טלפון + תוכן ההודעה (קוד, "יש עדכון בתיק") - **בלי מידע רפואי** | **[לאישור]** | טרם נבחר |
| ספק מייל של המשרד | מה שלקוחות שולחים למייל | **[לאישור: Google / Microsoft - מחוץ לישראל]** | קיים אצל המשרד |
| Anthropic (AI) | **מטא-דאטה של תיק בלבד**, בלי שם, ת"ז, טלפון, כתובת, ובלי תוכן רפואי (`policy.py`, `redact.py`). שליחת תוכן מסמך כבויה (`POLICY_MODE = METADATA_ONLY`) | ארה"ב | ממומש, מופעל רק עם מפתח API |
| המוסד לביטוח לאומי / משרד הביטחון | הגשת התביעה - בידי עורך הדין, מחוץ למערכת | ישראל | |

**העברה לחו"ל:** Anthropic, וכנראה גם ספק המייל. **[לאישור]** התאמה לתקנות העברת מידע אל מאגרי מידע שמחוץ לגבולות המדינה, וההסכם מול כל ספק (תקנה 15 - מיקור חוץ).

## 7. עיבוד אוטומטי

- **סיווג מסמכים** לפי כללים דטרמיניסטיים (`classify_rules.py`), בלי AI.
- **אישור/דחייה אוטומטיים** רק ב"לא קריא" וב"ברור, תואם וקריא היטב" (`doc_decision.py`); מסומן כאוטומטי, הפיך, וניתן לכיבוי. החלטה משפטית מהותית אינה מתקבלת אוטומטית.
- **מחשבונים** מציגים טווח עם הסתייגות; זכות חיצונית מוצגת רק אחרי אישור עו"ד.

## 8. רמת האבטחה [לאישור]

לפי התוספת הראשונה לתקנות 2017, מאגר שעיקר המידע בו רפואי משויך לרמה **בינונית**, ועולה ל**גבוהה** לפי מספר נושאי המידע או מספר בעלי ההרשאה. בהיקף הצפוי (משרד בהקמה, צוות קטן) ההערכה היא **בינונית** - אבל זו פרשנות שאינה שלי.

**ההמלצה המעשית:** לבנות לפי דרישות הרמה הגבוהה בכל מקום שזה זול. רובן כבר ממומשות (הצפנה, MFA, יומן צפייה, הרשאה לפי צורך). מה שהרמה הגבוהה מוסיפה ועוד חסר: **סקר סיכונים ומבחן חדירות כל 18 חודשים**, ודיון שנתי בהנהלה על אירועי אבטחה.

## 9. בעלי תפקיד

- **ממונה אבטחת מידע:** **[לאישור]** אם המשרד חייב בכך. גם אם לא - מומלץ שמישהו מחוץ לצוות הפיתוח יעבור על המסמכים האלה פעם אחת לפני העלייה.
- **ממונה הגנה על פרטיות (DPO, תיקון 13):** **[לאישור]** - ההערכה היא שמשרד קטן אינו חייב, אבל הבדיקה משפטית.
