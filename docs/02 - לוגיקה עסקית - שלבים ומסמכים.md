# לוגיקה עסקית — שלבי התביעה והמסמכים

## מסלול תביעת ביטוח לאומי (8 שלבים)

מוגדר ב-`assets/js/data.js` במערך `CLAIM_STAGES`:

| # | שלב | תיאור |
|---|---|---|
| 1 | פתיחת תיק ואיסוף מסמכים | ייפוי כוח, מסמכים רפואיים, תלושי שכר |
| 2 | הגשת התביעה לביטוח לאומי | טופס תביעה + אסמכתאות לסניף |
| 3 | בדיקת התביעה בסניף | פקיד התביעות בוחן זכאות עקרונית |
| 4 | זימון לוועדה רפואית | קבלת זימון והכנה מקדימה |
| 5 | ועדה רפואית מדרג ראשון | התייצבות, קביעת אחוזי נכות |
| 6 | קבלת החלטת הוועדה | פרוטוקול מתקבל ונבחן |
| 7 | הגשת ערר / ועדת עררים | ערר מנומק ודיון בוועדה לעררים |
| 8 | סיום התיק ותשלום הגמלה | החלטה סופית, חישוב רטרו, תשלום |

### כיצד מוצג השלב
- `caseFile.currentStage` קובע את המצב. כל שלב מקבל אחד משלושה מצבים:
  - `done` (מספר קטן מהנוכחי) — נקודה ירוקה + ✓ + תאריך השלמה מתוך `stageDates`.
  - `current` — נקודה זהובה עם הילה, תג "בשלב זה כעת".
  - `pending` — אפור, "ממתין".
- סרגל ההתקדמות מחשב `currentStage / 8` באחוזים.

> ⚠️ **הערה משפטית שהוטמעה במוצר:** לא כל תיק עובר את כל השלבים (למשל, תיק שהסתיים בשלב 6 ללא ערר). הצגת השלבים היא מסלול מלא, והשלבים העתידיים מסומנים כ"ממתין" ולא כמובטחים. בכותרת התחתונה נוספה הבהרה שהמידע אינו מהווה ייעוץ משפטי.

## רובריקת המסמכים

לכל מסמך ב-`caseFile.documents`:

| שדה | משמעות |
|---|---|
| `name` | שם המסמך כפי שהלקוח מבין אותו |
| `note` | הנחיה מדויקת (למשל "עד 6 חודשים אחורה") — מפחית העלאות שגויות |
| `required` | האם מסמך חובה — מסומן בתג אדום "חובה" |
| `status` | `missing` / `pending-review` / `approved` |
| `file`, `date` | שם הקובץ שהועלה ומועד ההעלאה |

### סינון
ארבע לשוניות עם מונים חיים: **הכל · מסמכים חסרים · בבדיקת המשרד · אושרו**.

### זרימת העלאה
1. הלקוח לוחץ "העלאה" על שורת מסמך ספציפי — או גורר קובץ לאזור הגרירה הכללי.
2. ולידציה: סוג קובץ (PDF/JPG/PNG) וגודל (עד 10MB).
3. אם ההעלאה כללית (ללא בחירת שורה) — הקובץ משויך אוטומטית **למסמך החובה החסר הראשון**.
4. הסטטוס משתנה ל-`pending-review`, המונים והסטטיסטיקות מתעדכנים, ומוצג טוסט אישור.
5. השינוי נשמר ב-`localStorage` תחת `bl_case_overrides_v1` — כך שהוא שורד רענון דף.
