אתר מעקב ללקוחות המשרד בתביעות ביטוח לאומי, וממשק ניהול פנימי לצוות.

## הפעלה

### 1. מסד נתונים

```powershell
.\scripts\pg-local.ps1 setup     # פעם אחת, ~330MB
.\scripts\pg-local.ps1 start
python -m server.db.keygen        # מדפיס מפתחות ת"ז ל-.env
python -m server.db.keygen init --dir $env:LOCALAPPDATA\nahmani-secrets   # מפתחות-על להצפנת קבצים
python -m server.db.apply         # סכמה + נתוני הדגמה
```

### סורק קבצים (פיתוח)

```powershell
.\scripts\clamav-local.ps1 setup     # פעם אחת: ClamAV + חתימות (~500MB)
.\scripts\clamav-local.ps1 start
```

### עיבוד מסמכים (worker)

```powershell
python -m server.worker --enqueue-missing   # קבצים clean שנשמרו לפני שלב 2
python -m server.worker                     # לולאה; --once לעבודה אחת
```

### התראות (notifier)

```powershell
python -m server.notifier          # סבב אחד
python -m server.notifier --loop   # כל 5 דקות
```

### 2. משתני סביבה (`.env` בשורש, אינו נכנס ל-git)

| משתנה | חובה | תפקיד |
|---|---|---|
| `PORTAL_ID_HMAC_KEY` | כן | HMAC ל-`national_id_lookup`. **שינויו פוסל את כל הלקוחות הקיימים** |
| `PORTAL_ID_ENC_KEY` | כן | הצפנת ת״ז לתצוגה. חייב להיות שונה מהקודם |
| `DATABASE_URL` | לא | ברירת מחדל: `postgresql://postgres@127.0.0.1:55432/portal` |
| `PORTAL_MODE` | לא | `demo` (ברירת מחדל) או `production` |
| `ANTHROPIC_API_KEY` | לא | בלעדיו הניתוח המקצועי מושבת |
| `PORTAL_STORAGE_DIR` | לא | ברירת מחדל: `var/uploads` |
| `PORTAL_SECRETS_DIR` | כן, להעלאה | תיקיית מפתחות-העל (`files_kek_v1`…). מחוץ לריפו. בלעדיה העלאה מחזירה 503 |
| `PORTAL_CLAMD_ADDR` | בייצור | `tcp://127.0.0.1:3310`. בלעדיו אין סריקה, וקבצים נשארים `pending` |
| `PORTAL_ALLOWED_ORIGINS` | בייצור | רשימת מקורות מותרים ל-CSRF |

## מה יש במערכת

### אזור הלקוח
- השלב הנוכחי בתביעה, סרגל התקדמות, וציר כל 8 השלבים.
- **"מה עליי לעשות עכשיו"** — כל המסמכים שחסרים או נדחו, במקום אחד.
- רשימת מסמכים עם ארבעה סטטוסים: חסר · בבדיקה · אושר · **נדחה** (עם סיבת הדחייה כלשונה).
- **צילום מסמך עם בדיקת איכות** — ראה למטה.
- **תגובה למשרד**: ארבע תגובות מהירות ("אין לי את המסמך", "צריך עזרה בהשגתו"…) ואפשרות לפרט בטקסט חופשי.
- עדכונים מהמשרד וכרטיס יצירת קשר.
- כפתור הגדלת טקסט, ניגודיות גבוהה, וסטטוס המסומן בסמל **ובטקסט** — לא בצבע בלבד.

### ממשק הניהול
- טבלת כל התיקים עם מוני עבודה פתוחה: ממתין לבדיקה · חסר ללקוח · פניות חדשות · חוסם שלב.
- **מצב טכני** — חישוב דטרמיניסטי (לא AI) של מה חוסם את התיק מלהתקדם, לפי `STAGE_DOC_REQUIREMENTS` של סוג התביעה.
- **דרישת מסמך מהלקוח** — מקטלוג לפי סוג תביעה או בהוספה חופשית. ההנחיה היא שדה חובה.
- אישור או דחייה של מסמכים; דחייה מחייבת סיבה שמוצגת ללקוח.
- עדכון שלב התביעה ושליחת עדכונים ללקוח.
- יומן פעולות הצוות.
- **ניתוח מקצועי** — ראה למטה.

## הסבר זכויות אחרי החלטת ועדה

כשמתקבלת החלטת ועדה, הלקוח רואה בראש האזור האישי בלוק ייעודי: מה נקבע, מה זה אומר, מה מגיע לו, ו**המועד האחרון להגשת ערר עם ספירת ימים**.

> 🔴 **התוכן המשפטי ב-`RIGHTS_EXPLAINER` הוא טיוטה ואינו מאושר.**
> כל ערך נושא `approved`. **כל עוד `approved` אינו `true`, ההסבר אינו מוצג ללקוח כלל** — במקומו הוא מקבל הפניה לפנות למשרד. זו התנהגות ברירת המחדל והיא מכוונת: עדיף שלקוח יתקשר מאשר שיקרא זכות שנוסחה לא נכון.
>
> על המשרד לכתוב את התוכן, לאמת אותו, ורק אז לסמן `approved: true`.

**מועד הערר מוזן ידנית על ידי המשרד ואינו מחושב על ידי המערכת.** מועדי ערר קריטיים ותלויים בנסיבות; המערכת רק סופרת ימים מהתאריך שהוזן ומדגישה אותו כשנותרו 14 ימים או פחות.

## בדיקת איכות הצילום

`assets/js/quality.js`. הלקוח מצלם את המסמך (או בוחר קובץ), והמערכת בודקת את איכות התמונה **לפני** ששולחת אותה. צילום שאינו קריא נחסם, והלקוח מקבל הסבר מה לתקן ולא רק מה השתבש.

**הבדיקה רצה כולה בדפדפן** — התמונה לא נשלחת לשום מקום לצורך הבדיקה, ולכן אין חשיפה של מידע רפואי.

| נבדק | איך |
|---|---|
| טשטוש | שונות הלפלסיאן |
| חשיכה / חשיפת יתר | בהירות ממוצעת, בשילוב ניגודיות |
| ניגודיות | סטיית תקן של הבהירות |
| רזולוציה | אורך הצלע הארוכה |
| צל | אחוז פיקסלים שחורים |
| סוג וגודל הקובץ | לפי סוג התוכן, לא לפי הסיומת |

**מה הבדיקה לא עושה:** היא אינה קוראת את המסמך ואינה יודעת אם זה המסמך הנכון. איכות תמונה בלבד.

**חשוב — דרך המשך:** אחרי 3 ניסיונות כושלים נפתחת ללקוח אפשרות "שליחה בכל זאת". קהל היעד כולל מבוגרים ופגועי תנועה, וחסימה מוחלטת פירושה לקוח שלא יכול להגיש כלל והתיק שלו נתקע. לחסימה קשיחה לחלוטין: `ALLOW_OVERRIDE_AFTER = 0` ב-`dashboard.js`.

> ⚠️ **הספים ב-`DocQuality.LIMITS` הם ערכי פתיחה ולא כוילו על צילומים אמיתיים.** הם נבדקו מול תמונות סינתטיות בלבד. יש לכוון אותם מול צילומים שלקוחות באמת מעלים.

## הניתוח המקצועי

עוזר לעורך הדין בלבד, לא גלוי ללקוח. מציע כיווני המשך, מה כדאי לומר ללקוח, ואילו השלמות תיעוד חסרות.

**מה נשלח החוצה:** מטא-דאטה של התיק בלבד — סוג תביעה, שלב, ושמות וסטטוסים של מסמכים.
**מה לא נשלח:** שם הלקוח, תעודת זהות, טלפון, אימייל, שמות קבצים, וכל תוכן רפואי.

המדיניות מרוכזת ב-`server/policy.py`, שנכתב כדי שאפשר יהיה לקרוא אותו במלואו ולהחליט אם הוא בטוח. יש בו שכבת רשת אחרונה שנכשלת בקול אם פרט מזהה נכנס בטעות.

**לביקורת עצמית** — נקודת קצה שמראה בדיוק מה היה נשלח, בלי לשלוח דבר:

```
POST /api/office/assist/preview
```

הפלט של המודל הוא **חומר לשיקול דעת** ואינו ייעוץ משפטי או רפואי. המודל אינו שולח דבר ללקוח: הוא יכול לנסח טיוטה, ועורך הדין עורך ושולח בעצמו.
